# COMPONENT_SPEC: 간단한 할 일 목록 웹 앱

- 문서 상태: 초안
- 기준 문서: docs/PRD.md, docs/API_SPEC.md
- 작성일: 2026-10-23

## 1. 개요

화면은 한 페이지(`/`)뿐이다. 이 페이지에서 할 일 추가(F-01), 목록 보기(F-02), 완료 전환(F-03), 삭제(F-04)를 모두 한다.

- 화면에 보이는 것은 제목, 체크박스, 삭제 버튼뿐이다. 만든 시각(`createdAt`)은 정렬에만 쓰고 화면에 보여주지 않는다.
- 컴포넌트 파일은 `src/components/`에 둔다. 페이지 파일은 `app/page.tsx`다.
- `Todo` 타입은 DATA_MODEL.md, `ApiErrorResponse` 타입은 API_SPEC.md를 따른다.

## 2. 컴포넌트 트리

```
app/page.tsx (Page)
└── TodoApp            ← 상태와 API 호출을 모두 맡는다
    ├── TodoForm       ← 제목 입력과 "추가" 버튼
    ├── (상태 문구)     ← 로딩 / 목록 에러 / 동작 에러
    └── TodoList       ← 목록, 빈 목록 문구
        └── TodoItem   ← 할 일 한 줄 (체크박스 + 제목 + 삭제 버튼)
```

### 역할 나누기

| 컴포넌트 | 파일 | 하는 일 | API 호출 |
|----------|------|---------|----------|
| Page | app/page.tsx | TodoApp을 화면에 놓는다 | 안 함 |
| TodoApp | src/components/TodoApp.tsx | 할 일 목록, 로딩, 에러 상태를 가진다. API를 부르고 결과로 상태를 바꾼다 | 함 (유일) |
| TodoForm | src/components/TodoForm.tsx | 제목 입력, 화면 1차 검사, 추가 요청 전달 | 안 함 |
| TodoList | src/components/TodoList.tsx | 목록을 그리거나, 비었으면 빈 목록 문구를 보여준다 | 안 함 |
| TodoItem | src/components/TodoItem.tsx | 할 일 한 줄을 그리고 체크/삭제 동작을 전달한다 | 안 함 |

API를 부르는 곳을 TodoApp 하나로 모은다. 나머지 컴포넌트는 받은 값(Props)을 그리고, 사용자 동작을 위로 알리기만 한다. 그래서 테스트하기 쉽다.

TodoApp은 브라우저에서 동작해야 하므로 파일 맨 위에 `"use client"`를 쓴다.

## 3. Props 타입

아래는 예시이며, 실제 파일은 구현 단계에서 만든다.

### Page

Props 없음.

### TodoApp

Props 없음. 아래 상태를 스스로 가진다.

```ts
// TodoApp 안의 상태 (Props 아님)
todos: Todo[];                  // 화면에 보여줄 목록 (최신순)
isLoading: boolean;             // 처음 목록을 불러오는 중인지
loadError: string | null;       // 목록 불러오기 실패 문구
actionError: string | null;     // 전환/삭제 실패 문구
isAdding: boolean;              // 추가 요청 중인지
addError: string | null;        // 서버가 돌려준 추가 실패 문구
pendingIds: string[];           // 전환/삭제 요청 중인 할 일 id
```

### TodoForm

```ts
type TodoFormProps = {
  // 추가 요청. 앞뒤 공백을 지운 제목을 넘긴다. 성공하면 true, 실패하면 false
  onAdd: (title: string) => Promise<boolean>;
  // 입력창 글자가 바뀔 때 알린다 (TodoApp이 추가 에러 문구를 지우는 데 쓴다)
  onTitleChange: () => void;
  // 추가 요청 중이면 true (입력창과 버튼을 막는다)
  isSubmitting: boolean;
  // 서버가 돌려준 에러 문구. 없으면 null
  errorMessage: string | null;
};
```

- 화면 1차 검사 문구는 TodoForm이 스스로 가진다. 검사 문구가 있으면 그것을, 없으면 `errorMessage`를 보여준다.

### TodoList

```ts
type TodoListProps = {
  todos: Todo[];                                      // 최신순으로 정렬된 목록
  pendingIds: string[];                               // 요청 중인 할 일 id
  onToggle: (id: string, completed: boolean) => void; // 체크박스를 눌렀을 때
  onDelete: (id: string) => void;                     // 삭제 버튼을 눌렀을 때
};
```

### TodoItem

```ts
type TodoItemProps = {
  todo: Todo;
  isPending: boolean;                                 // 요청 중이면 체크박스와 삭제 버튼을 막는다
  onToggle: (id: string, completed: boolean) => void; // 바꿀 값(현재의 반대)을 넘긴다
  onDelete: (id: string) => void;
};
```

## 4. 사용자 동작과 결과

화면은 "낙관적 업데이트"(서버 응답 전에 먼저 바꾸기)를 하지 않는다. 서버가 성공을 알려준 뒤에만 화면을 바꾼다. 그래서 실패하면 목록은 그대로다.

### 4.1 페이지 열기 / 새로고침 (F-02, F-05)

| 단계 | 결과 |
|------|------|
| 페이지가 열림 | TodoApp이 `GET /api/todos`를 보낸다. 로딩 문구를 보여준다 |
| 성공 (200) | 받은 배열을 그대로 목록에 보여준다 (서버가 이미 최신순으로 정렬함) |
| 성공했는데 빈 배열 | 빈 목록 문구를 보여준다 |
| 실패 (500 또는 연결 실패) | 목록 대신 목록 에러 문구를 보여준다. 입력창은 막는다 |

### 4.2 할 일 추가 (F-01)

| 사용자 동작 | 결과 |
|-------------|------|
| 제목을 적고 "추가" 버튼 클릭 또는 Enter | 앞뒤 공백을 지운 제목으로 1~100자 검사를 한다 |
| 검사 실패 (빈 제목, 공백만, 101자 이상) | 요청을 보내지 않는다. 입력창 아래에 검사 문구를 보여준다. 입력한 내용은 그대로 둔다 |
| 검사 통과 | 앞뒤 공백을 지운 제목으로 `POST /api/todos`를 보낸다. 입력창과 버튼을 막고 버튼 글자를 "추가 중..."으로 바꾼다 |
| 성공 (201) | 응답받은 할 일을 목록 맨 위에 넣는다. 입력창을 비우고 문구를 지운다. 입력창에 다시 커서를 둔다 |
| 실패 (400, 500) | 응답의 `error.message`를 입력창 아래에 보여준다. 입력한 내용은 그대로 둔다 |
| 실패 (연결 실패, 응답이 JSON이 아님) | 연결 실패 문구를 입력창 아래에 보여준다 |
| 입력창에 다시 글자를 입력 | 보이던 검사 문구와 추가 에러 문구를 지운다 |

- 입력창에 `maxLength`를 쓰지 않는다. 101자 이상을 입력하면 검사 문구로 알려준다.
- 글자 수는 API_SPEC과 같게 이모지 하나를 1자로 센다. 검사 함수는 서버와 같은 것을 쓴다.

### 4.3 완료/미완료 전환 (F-03)

| 사용자 동작 | 결과 |
|-------------|------|
| 미완료 할 일의 체크박스 클릭 | `PATCH /api/todos/{id}`에 `{ "completed": true }`를 보낸다. 그 할 일의 체크박스와 삭제 버튼을 막는다 |
| 완료된 할 일의 체크박스 클릭 | `{ "completed": false }`를 보낸다. 나머지는 위와 같다 |
| 성공 (200) | 응답받은 할 일로 그 줄을 바꾼다. 완료면 체크 표시와 함께 제목에 취소선을 긋는다. 목록 순서는 바뀌지 않는다 |
| 실패 (404, 500, 연결 실패) | 체크 상태는 그대로 둔다. 목록 위에 동작 에러 문구를 보여준다 |

### 4.4 할 일 삭제 (F-04)

| 사용자 동작 | 결과 |
|-------------|------|
| 삭제 버튼 클릭 | 확인 창 없이 바로 `DELETE /api/todos/{id}`를 보낸다. 그 할 일의 체크박스와 삭제 버튼을 막는다 |
| 성공 (204) | 그 할 일을 목록에서 뺀다. 마지막 하나였다면 빈 목록 문구를 보여준다 |
| 실패 (404, 500, 연결 실패) | 목록은 그대로 둔다. 목록 위에 동작 에러 문구를 보여준다 |

### 4.5 동작 에러 문구 지우기

- 다음 전환·삭제·추가를 시작하면 보이던 동작 에러 문구를 지운다.

## 5. 상태별 문구

| 상태 | 위치 | 문구 |
|------|------|------|
| 목록 로딩 중 | 목록 자리 | 할 일을 불러오는 중... |
| 빈 목록 | 목록 자리 | 아직 할 일이 없습니다. 위에서 할 일을 추가해 보세요. |
| 목록 불러오기 실패 | 목록 자리 | 할 일을 불러오지 못했습니다. 페이지를 새로고침해 주세요. |
| 추가 중 | "추가" 버튼 | 추가 중... |
| 화면 1차 검사 실패 | 입력창 아래 | 제목은 1~100자로 입력해 주세요. |
| 추가 실패 (서버 응답) | 입력창 아래 | 서버가 준 `error.message` 그대로 |
| 전환·삭제 실패 (서버 응답) | 목록 위 | 서버가 준 `error.message` 그대로 |
| 연결 실패 (서버에 닿지 못함, 응답을 읽을 수 없음) | 해당 에러 위치 | 서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요. |

서버가 주는 문구(API_SPEC 에러 코드 목록):

| code | 문구 |
|------|------|
| INVALID_REQUEST | 요청 형식이 올바르지 않습니다. |
| INVALID_TITLE | 제목은 1~100자로 입력해 주세요. |
| INVALID_COMPLETED | 완료 여부 값이 올바르지 않습니다. |
| NOT_FOUND | 할 일을 찾을 수 없습니다. |
| INTERNAL_ERROR | 잠시 후 다시 시도해 주세요. |

## 6. 접근성과 테스트를 위한 약속

Testing Library로 "사용자가 보는 것" 기준으로 찾을 수 있게 아래를 지킨다.

| 요소 | 약속 |
|------|------|
| 제목 입력창 | 라벨 "할 일" (`getByLabelText("할 일")`로 찾음) |
| 추가 버튼 | 글자 "추가" (`getByRole("button", { name: "추가" })`) |
| 체크박스 | 라벨이 할 일 제목 (`getByRole("checkbox", { name: "우유 사기" })`) |
| 삭제 버튼 | 접근성 이름 "우유 사기 삭제" (`getByRole("button", { name: "우유 사기 삭제" })`) |
| 목록 | `<ul>` / `<li>`로 그린다 (`getAllByRole("listitem")`) |
| 에러 문구 | `role="alert"` (화면 읽기 프로그램이 바로 읽어줌) |
| 로딩 문구 | `role="status"` |

## 7. 버전별 차이

| 버전 | TodoApp의 데이터 처리 | 로딩 문구 | 연결 실패 문구 |
|------|------------------------|-----------|----------------|
| v0.1 | API 없이 상태 안에서 직접 추가·전환·삭제 (id, createdAt도 화면에서 만든다) | 없음 | 없음 |
| v0.2~ | 4장대로 API 호출 | 있음 | 있음 |

- 컴포넌트 트리와 TodoForm·TodoList·TodoItem의 Props는 모든 버전에서 같다. 바뀌는 것은 TodoApp 안쪽뿐이다.
- v0.1에서도 제목 검사 규칙과 최신순 규칙은 같다.
