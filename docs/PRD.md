# PRD: 간단한 할 일 목록 웹 앱

- 문서 상태: 초안
- 기준 문서: docs/IDEA.md
- 작성일: 2026-10-23

## 1. 목표

혼자 쓰는 사람이 할 일을 빠르게 적고, 끝낸 일을 체크하고, 필요 없는 일을 지울 수 있는 간단한 웹 앱을 만든다.

- 기능은 꼭 필요한 것만 둔다. 화면을 열면 바로 쓸 수 있어야 한다.
- 새로고침해도 적어 둔 할 일이 사라지지 않아야 한다.
- 버전 로드맵(v0.1 → v1.0)에 따라 화면, API, DB, 배포 순서로 조금씩 키운다.

## 2. 대상 사용자

- 자기 할 일을 혼자 관리하는 개인 사용자 1명
- 로그인이나 다른 사람과의 공유가 필요 없는 사람
- 마감일, 카테고리 같은 복잡한 관리 기능보다 "적고, 체크하고, 지우기"만 원하는 사람

## 3. 기능 목록

| ID | 기능 | 설명 | 도입 버전 |
|------|------|------|-----------|
| F-01 | 할 일 추가 | 제목을 입력해 할 일을 추가한다. 제목은 필수이며, 앞뒤 공백을 지운 뒤 1~100자여야 한다. 공백만 있으면 빈 제목으로 본다. 조건에 맞지 않으면 추가되지 않는다. | v0.1 |
| F-02 | 할 일 목록 보기 | 등록된 할 일을 추가한 시각 기준 최신순(가장 최근에 추가한 것이 맨 위)으로 보여준다. | v0.1 |
| F-03 | 완료/미완료 전환 | 각 할 일의 체크박스로 완료와 미완료 상태를 바꾼다. | v0.1 |
| F-04 | 할 일 삭제 | 할 일 하나를 목록에서 삭제한다. | v0.1 |
| F-05 | 데이터 유지 | 새로고침해도 할 일 목록이 그대로 남아 있다. | v0.2 (서버 메모리), v0.3 (DB) |

### 버전별 데이터 보관 위치

| 버전 | 보관 위치 | F-05 충족 여부 |
|------|-----------|----------------|
| v0.1 | 브라우저 메모리 | 충족하지 않음 (새로고침 시 사라짐) |
| v0.2 | 서버 메모리 | 새로고침은 유지, 서버 재시작 시 사라짐 |
| v0.3 | DB (MySQL) | 충족 (서버 재시작 후에도 유지) |

## 4. 사용자 스토리

| ID | 관련 기능 | 사용자 스토리 |
|------|-----------|---------------|
| US-01 | F-01 | 사용자로서 해야 할 일의 제목을 입력해 목록에 추가하고 싶다. 그래야 잊지 않는다. |
| US-02 | F-01 | 사용자로서 제목을 비우거나, 공백만 넣거나, 100자를 넘기면 추가되지 않기를 원한다. 그래야 목록이 깔끔하게 유지된다. |
| US-03 | F-02 | 사용자로서 가장 최근에 추가한 할 일을 맨 위에서 보고 싶다. 그래야 방금 적은 일을 바로 확인할 수 있다. |
| US-04 | F-03 | 사용자로서 끝낸 일을 체크해 완료로 표시하고 싶다. 그래야 남은 일과 끝낸 일을 구분할 수 있다. |
| US-05 | F-03 | 사용자로서 잘못 체크한 일을 다시 미완료로 되돌리고 싶다. 그래야 실수를 고칠 수 있다. |
| US-06 | F-04 | 사용자로서 필요 없어진 할 일을 삭제하고 싶다. 그래야 목록에 쓸모없는 항목이 남지 않는다. |
| US-07 | F-05 | 사용자로서 새로고침하거나 다시 접속해도 할 일 목록이 그대로 있기를 원한다. 그래야 안심하고 기록할 수 있다. |

## 5. 범위 밖

이번 제품 범위에서 만들지 않는다.

- 로그인 / 회원가입
- 다른 사람과 공유
- 알림
- 마감일
- 카테고리

위 목록 외에도 이 문서에 없는 기능은 추가하지 않는다.

## 6. 성공 기준

### 기능 기준

- F-01: 앞뒤 공백을 지운 제목이 1~100자면 추가되고, 빈 제목·공백만 있는 제목·101자 이상 제목은 추가되지 않는다. 저장된 제목에는 앞뒤 공백이 없다.
- F-02: 목록이 항상 최신순으로 표시된다.
- F-03: 체크박스를 누르면 완료/미완료가 바뀌고, 화면에 바로 반영된다.
- F-04: 삭제한 할 일은 목록에서 바로 사라진다.
- F-05: v0.3 이후, 새로고침과 서버 재시작 후에도 추가·완료·삭제 결과가 그대로 유지된다.

### 품질 기준

- 각 기능에 대응하는 테스트(docs/TEST_CASES.md)가 모두 통과한다.
- 테스트를 삭제하거나 skip하지 않은 상태에서 통과한다.
- 처음 쓰는 사용자가 설명 없이 추가·완료·삭제를 해낼 수 있다.

### 버전 완료 기준

- v0.1: F-01~F-04가 브라우저에서 동작한다.
- v0.2: F-01~F-04가 API를 통해 동작하고, 새로고침해도 목록이 유지된다.
- v0.3: 데이터가 DB에 저장되어 서버 재시작 후에도 유지된다.
- v1.0: 배포된 주소에서 위 기능이 모두 동작한다.
